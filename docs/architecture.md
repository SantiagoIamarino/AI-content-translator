# Pipeline and persistence

Jobs contain atomic config/manifest snapshots and derived files. States are pending, running, awaiting_translation, awaiting_repair, awaiting_repair_review, awaiting_source_review, failed, partial, complete. Manual and auto runners share the same stages; auto alone completes provider handoffs while holding the job operation lock.

An end-to-end map of the current stages, handoffs, retry budgets, feedback loops, eligibility order and cache identities (as of `8eb4e4c`) is in [frontier-review-report-20261017.md §9](frontier-review-report-20261017.md#9-funcionamiento-actual-del-pipeline-estado-en-8eb4e4c). README's "What runs" table predates the quality/performance presets and source resolution.

For source-events jobs, a compact revision whose exact English lacks a matching
review reaches `awaiting_repair_review` before scheduling, mixing, export or
validation. Manual `run`/`resume` stops with exit 2 and a hint to use configured
`auto` with the original video/name; it never invokes a provider itself. If review
is disabled, this handoff stays blocked. Auto reviews under its existing lock,
then resumes scheduling. Disputed and last-round revised-unconfirmed verdicts
remain unvoiced/partial; resuming does not grant them more rounds. Explicit
`leave_unresolved` decisions and historical jobs without source-events retain
their previous policy. No separate manual review-response acceptance command is
introduced.

A saved stage is reusable only when its input fingerprint and required outputs match. Source changes in an existing job are rejected. Inspect separates stream/container metadata from video-only packet timing. Extract uses independent track fingerprints and header-only alignment; migration can reuse legacy extracted PCM while recalculating timing metadata.

Source ASR processes overlapping windows sequentially, checkpointing each result under its mic/model/window identity. Boundary words are owned by one window according to their midpoint, then energy-based segmentation adjusts/merges approximate cues. RMS is calculated by block rolling sums; voiced intervals are indexed in SQLite with an 8 MiB page cache. No full recording waveform or sample-by-sample Python mask loop is needed. Metadata and interval index size still grow with content.

Provider batches are immutable request identities. Matching validated responses are reused independently before aggregate acceptance. Attempt state is fsynced before invocation; responses and metadata are atomically replaced and directory renames synced. A missing response after an in-flight attempt is an uncertain outcome. Local processes are cleaned up, but external billing cannot be transactional with the local filesystem.

Synthesis identity covers text, seed, reference bytes/transcript and Qwen settings; new jobs also bind the frozen model snapshot revision. New WAV writes precede atomic metadata and include a waveform hash. The shared Qwen backend rejects a settings change in a running process and the prompt includes the reference content hash.

Quality identity is independent: generated bytes/cache identity, reference, checker source/version, full quality config, ASR weights, language, worker and environment versions. Changing verification settings reruns verification only. Failed/unavailable ASR checks are not cached as successful checks. CUDA-to-CPU fallback uses a distinct verification identity. Per-line v2 checkpoints and the ledger retain candidate history, while independent `cache/quality` files checkpoint completed candidate verification immediately.

Legacy job config snapshots, synthesis cache keys and matching completed transcript cue IDs remain usable. Legacy quality records are not trusted as v2 verification results; the old generated WAV can be verified again. Existing outputs are not deleted to migrate. Altering source/segmentation configuration deliberately invalidates the transcript/translation chain.

Fit retains the original RMS/tempo rules, bounded quality/alternate seeds, limited earlier placement into unused silence and faithful compact repair. Scheduling outcomes remain in `schedule/summary.json`; final assembler/headroom outcomes are separate in `mix/placed_summary.json`, preventing a temporary mix failure from permanently erasing a schedulable cue.

Quality-preset jobs extend the same stages. Transcribe adds a second Whisper hearing (`transcribe/second_pass.json`) and short-pause utterance joins before cue IDs are assigned. The translation handoff, under the held job lock, runs context → contextual translation batches → bounded bilingual review rounds (with optional back-translation for disputed lines only before another review round can consume it) and then the normal `accept_translation`; the request identity includes the context so a saved response is reused only with the same context. Schedule uses best-of-N selection (`selection_summary`) and the unified presentation path (`presentation_version=2`). After validation, `report/risk.md` is rebuilt only when its inputs change. See docs/quality.md.

Mixing loads only a block and one cue, applies safe cue gain to the voice, and writes the actual voice and mix as FLOAT PCM. Game samples remain unchanged. Validation reads corresponding blocks and checks `mix-(game+voice)`. MP4/MKV exports explicitly map one copied picture and one English audio track. A successful bitstream comparison is independent of unavailable frame counts. Decoded English audio is separately checked in bounded pipe reads for non-finite samples/full-scale overshoot. Approximate duration, codec overshoot and unreviewed energy gaps prevent complete status. See README for partial/headroom policies.

New snapshots default to `export.spanish_compare=false`; absent fields in existing
snapshots mean legacy-on. English mix fingerprints retain their prior identity.
The optional `mix/spanish_compare.json` checkpoint binds source hash, mixed
ordinal, container and comparison bytes independently. Missing/changed requested
comparisons are rebuilt without remixing/remuxing English. A known legacy output
with its exact saved command can be adopted without remux. An English checkpoint
survives a later optional-output failure. Disabling never deletes an older file.

Validation v7 conditionally hashes/probes/decodes the comparison; disabled checks
are `not_requested`, non-required and `ok=null`. English source/decode/bitstream,
PCM, timing, verification and coverage gates are unchanged. An unused leftover
comparison cannot invalidate or satisfy validation. Risk previews use original
mixed audio with explicit audio ordinal and absolute picture-origin seeking;
their cache binds the source, mapping and preview settings. Offline picture-only
evaluation helpers can use a saved English copied picture if the original is
missing, with their existing limitation that this cannot revalidate the original.

### Source resolution handoff (batch 5)

With explicit source-resolution configuration, `run_job` returns the
`awaiting_source_review` handoff before scheduling/mixing. `run_unattended` invokes
the synchronous resolver under its existing owned lock. No additional runner or
lock reacquisition is introduced. `fidelity.eligibility` keeps source confidence,
translation fidelity and synthesis eligibility separate; the targeted acceptor,
cache-miss scan, scheduler and validator consume that decision.

Per-evidence episodes reserve their hearing/semantic budgets atomically before
calls. An exact pending request resumes through the existing provider helpers.
The manifest records accepted decisions and an acceptance receipt before the
sidecar budget save, allowing a crash between those writes to recover without
reapplying a split or resetting counters. Saved responses can be revalidated with
their original provenance; invalid rows never become approvals. Exhausted
invalid rows are recorded separately so they cannot poison a valid neighbor.

Only eligible schedules/downstream artifacts are invalidated. Source policy is
versioned independently from raw ASR and synthesis identities. Identical source
spans retain accepted historical English/provenance when source diagnostics are
recomputed from cached evidence. Raw takes/ASR remain reusable. Supported splits
retain the parent in the manifest, introduce stable child lineage, and keep
unknown remainder rows unvoiced and technically partial. Frozen global context
can still be read against reconstructed original parent spans. A confirmed compact
repair may rebind exact English only when its source evidence is still current;
it cannot confirm a changed microphone/span/readings or grant another source budget.

### Cue-scoped translation and review recovery

Translation and bilingual review batches isolate decisions only after the saved
response has a valid envelope and an exact, unique set of requested IDs. Each row
is then checked against its original source and exact current English. Valid rows
survive a sibling's content error; malformed envelopes, missing/duplicate/foreign
IDs, uncertain provider outcomes, authentication/quota failures and other
infrastructure errors remain batch-level stops. Invalid cue subsets receive one
separate persisted recovery identity by default (`content_recovery.max_attempts`,
bounded to 1..2), with explicit validator feedback and the original row evidence.
Exhausted cues are marked withheld and remain silent in the voice track; independent
batches continue. A revised review line still needs a later `ok` verdict on that
exact text. `report/omissions.json` and `.md` bind each omitted cue and its reason
to the final export hash and validation fingerprint. Such an export is partial.
